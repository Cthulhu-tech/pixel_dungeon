# План реализации полного порта

План — последовательность рабочих задач, а не отчёт о готовом коде. Общие правила приёмки: AGENTS.md и PARITY.md. Новый код только в `web/`; baseline не трогать. Статус на создание документа: P00 начат аудитом, P01–P10 не начаты.

## Порядок и зависимости

```text
P00: источник/реестр/oracle ──> P02: совместимость/ядро
P01: web/toolchain ──────────> P03: первый интеграционный срез
P02 + P03 ──> P04/P05/P06 ──> P07/P08 ──> P09 ──> P10
```

P01 можно делать параллельно с подготовкой исходной сборки P00. Контракты сохранения и первый round trip появляются на P03, а не в самом конце. UI-интеграция тоже начинается на P01/P03; P08 — полное покрытие экранов, а не первое появление UI. Независимые части не блокируются отсутствующим fixture соседней области.
