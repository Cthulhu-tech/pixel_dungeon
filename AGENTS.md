# Pixel Dungeon: обязательный вход для исполнителя

## Цель

Полностью перенести **именно исходную игру этого репозитория 1:1** с Java/Android на браузерный JavaScript. Основной код — strict TypeScript; Vite, Phaser 4, XState, Zustand vanilla, phaser4-rex-plugins обязательны. Navcat — только кандидат, не обязательная зависимость.

Эталон: `Cthulhu-tech/pixel_dungeon@ce7f241515fd5c040fcf18b4beb5b7a49d9d535f`, Pixel Dungeon **1.9.1**, versionCode **74**. Не Shattered Pixel Dungeon, не сторонний TS/PixiJS-порт и не подвижный upstream HEAD. 1:1 относится к поведению, контенту, интерфейсу, графике, анимациям и звуку; Java-пакеты/Android API/глобальные объекты копировать не требуется. Прототип или первый этаж не являются завершённым переносом.

## Обязательное чтение

1. Этот файл и [MANDATORY_RULES](docs/port/MANDATORY_RULES.md) — применимые обязательные правила из PSX/CORE с явно записанными адаптациями.
2. [STATUS](docs/port/STATUS.md) и активная задача единого [PLAN](docs/port/PLAN.md).
3. Для первого входа — [README](docs/port/README.md). Далее только относящиеся к задаче [ARCHITECTURE](docs/port/ARCHITECTURE.md), [PARITY](docs/port/PARITY.md), [STACK](docs/port/STACK.md), README владельцев, public contracts и вызывающий код.
4. Закреплённый `docs/port/source-baseline.json`, нужные исходные методы и соответствующие записи source-map/reference fixtures.

После восстановления контекста сначала проверить действительный checkpoint. Не перечитывать всю историю после каждой правки и не создавать вторую очередь в чатах/Issues. Новые явные решения пользовательницы фиксировать в документах; не менять требования для удобного закрытия задачи.

## Ограничения, которые нельзя пропустить

- **PD-R20: агенту запрещено запускать, подключать или автоматизировать браузер**, в том числе Chrome/Edge/Chromium, CDP, Playwright/Puppeteer и запускающие их scripts/workflows. Наличие `test:e2e` в существующей заготовке не разрешает его запуск. Проверки агента — безбраузерные; реальную визуальную/input/audio приёмку выполняет человек. Нет evidence — NOT_VERIFIED, а не успешный результат по build.
- **PD-R07: собственные type/interface/type-only контракты только в `web/src/types/**/*.d.ts`**, разделённых по владельцам. Нет imports/exports/re-exports типов. Runtime `index.ts` экспортирует значения/классы/фабрики. Переносимость проверяется отдельным host с только нужными declarations/dependencies, не со всеми globals проекта.
- **PD-R11: собственный JSON — trusted immutable configuration.** Не вводить runtime/build schema validators, normalization, coercion, defaults, defensive cloning/freezing. Это не отменяет проверку недоверенных saves/ввода у boundary и независимый parity с оригиналом.
- **PD-R15/16: один Phaser 4 WebGL canvas/runtime.** Вся non-UI графика использует project shader path; UI через Phaser/rex. Собственные shader stages только в отдельных owner-local `.glsl`, не строках/генерации в TS/JS. Исходные textures/pixels сохраняются. Нет Canvas/DOM fallback, второго renderer или заимствованного WebGPU/React-движка.
- **PD-R04–06: один владелец, публичные границы, один composition root.** Домен не импортирует frameworks/DOM/storage/adapters. XState — orchestration, Zustand — UI projections, Phaser/rex — presentation. Нет cycles, deep imports, второго gameplay store, service locator и import-time side effects.

Это краткие указатели, не замена полного MANDATORY_RULES. Специфические числа слотов, 3D physics/Navcat/LOD, контент и старые task IDs PSX/CORE не переносятся в Pixel Dungeon.

## Неприкосновенный оригинал и точность

Не удалять, переносить или переписывать исходные `src/`, `assets/`, `res/`, `AndroidManifest.xml`, `LICENSE.txt`. Новый runtime — `web/`; исходный baseline не меняется без отдельного решения. Сохранять авторство/лицензии; фиксировать provenance каждого поведения и ассета. Внешняя PD-classes — необходимая часть источника, её сборочная совместимость требует проверки, а не предположения.

Не менять баланс, числа/вероятности, цены, AI, порядок действий/эффектов, путь, FOV, генерацию, тексты или UI ради улучшения. Не исправлять наблюдаемый баг оригинала попутно: записать расхождение. Реальные вопросы безопасности/платформы решать явно.

Случайность и внешнее время приходят через порты. Сохранять существенную Java-семантику float/int/casts/overflow и порядок коллекций; не обещать одинаковый результат от JS Math.random/Set. Оригинальные PathFinder/ShadowCaster/Ballistica и scheduler нельзя подменять удобной библиотекой без доказательства.

Логическое время — не frame delta. При этом `sprite.isMoving`, `Actor.next()` и места mutations в animation callbacks сохраняются через явные continuation IDs; headless adapter воспроизводит исходный порядок. Не переносить весь результат автоматически в начало/конец анимации.

Не генерировать новый арт. Конвертации атласов/метрик воспроизводимы и сверяются с оригиналом. Переносимость и оптимизация не оправдывают урезание игры.

## SOLID / KISS / DRY / OOP / DDD

Модульный монолит; отдельная область логики со своим владельцем, минимальным public API, README и тестами. Entity защищает инварианты, функции реализуют алгоритмы, JSON хранит исходные данные. Композиция предпочтительнее наследования ради доступа к состоянию. Общий код не должен стирать реальные различия правил оригинала.

Не создавать пустые слои, BaseManager/BaseService, общий mutable GameState, EventBus вместо зависимостей или framework ради будущего. Нет жёстких требований по числу строк/классов; обоснование — реальная граница, тест или extraction. Без any/type bypasses, dead code и нерелевантных переписываний. Оптимизировать практические расходы без микротюнинга и изменения поведения.

## Цикл одной задачи

1. Найти исходные входы, все ветки и побочные эффекты; определить owner/контракты/lifecycle.
2. Зафиксировать expected от независимого оригинала и способ проверки, включая ручную browser evidence при необходимости.
3. Перенести небольшое законченное поведение в правильном модуле; UI и save codecs добавлять вместе с ним.
4. Выполнить применимые **безбраузерные** unit/contract/parity/typecheck/build/architecture checks. Для docs-only — проверка документации/ссылок/diff. Не выдумывать результаты и не добавлять запрещённую content validation.
5. Проверить затронутые взаимодействия/cleanup, обновить owner docs, source-map, задачу и STATUS; затем коммитить.

Статус без независимой проверки — IMPLEMENTED_UNVERIFIED, не VERIFIED. Нельзя пропускать героев, предметы, окна, боссов или редкие ветки. Пустой suite, пройденный build и synthetic fixture не доказывают полный порт.

При блокере записать точную область/причину, не заменять её заглушкой и продолжать независимую разрешённую работу. Новая игра не используется как fallback для повреждённого save. Совместимость с исходной Java и импорт оригинальных saves рассматриваются явно; запрет скрытых compatibility workarounds их не отменяет.

## Текущий checkpoint и отчёт

Inventory/source-map и начальный `web/` уже присутствуют; не создавать их повторно по устаревшему отчёту. P01-RULES согласует существующую заготовку с импортированными требованиями. Эта запись не означает, что правила уже автоматически enforced или что тесты прошли.

В конце сессии обновлять STATUS: реально изменённые файлы/поведение, точные выполненные проверки/результаты, revision, непроверенные области, блокеры и следующий шаг. Один package manager/lockfile; временное только в root `tmp/`. Никаких выдуманных процентов и отчётов о несуществующих прогонах.
